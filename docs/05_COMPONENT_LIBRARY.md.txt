# COMPONENT LIBRARY

## Purpose

This document defines every reusable UI component used throughout the portfolio.

New components should only be introduced when they solve a real problem.

Consistency is preferred over variety.

---

# INTRO

Purpose

Create an emotional first impression.

Rules

• Full screen
• Cinematic
• Plays once
• Smooth transition into homepage
• No skip button unless accessibility requires it

---

# SECTION TITLE

Purpose

Introduce a new chapter.

Rules

• Large editorial typography
• Plenty of whitespace
• Never compete with imagery

---

# SELECTED WORK CAROUSEL

Purpose

Present the curated projects, one at a time.

Rules

• Large imagery
• Minimal text
• The centre card is the link; a side card brings itself to the centre
• Hover is subtle
• Image remains the hero
• Holds still under the pointer or keyboard focus

---

# CATEGORY CARD

Purpose

Represent a creative discipline.

Rules

• Equal dimensions
• Large cover artwork
• Live HTML title
• Entire card clickable
• Dark overlay
• Gentle image zoom on hover
• No text beneath the image

---

# IMAGE BLOCK

Purpose

Display artwork.

Rules

• Prioritize image quality
• Crop intentionally
• Never stretch
• Allow generous spacing

---

# TEXT BLOCK

Purpose

Support imagery.

Rules

• Keep concise
• Maximum readability
• Never dominate the layout

---

# BUTTON

Purpose

Guide interaction without demanding attention.

Rules

• Minimal styling
• Clear hierarchy
• Consistent hover behavior

---

# PROJECT PAGE

Every case study is bespoke, built to its own supplied reference board
(10_DECISION_LOG.md, 2026-08-30) — not a shared Hero / Challenge / Process
/ Outcome / Gallery template. What every project page shares:

1. One h1 (screen-reader-only where the title is part of the artwork)
2. Exit navigation: two doors side by side at the very bottom — back to the project's category on the left, the next project in that same category on the right, wrapping around (ProjectExitNav). A project with no sibling in its category ends with a single full-width back door instead: to the categories for Graphic T's (Apparel Design's only project), to its category listing otherwise.

A project with no case study of its own opens where it lives instead (e.g. a design in the Apparel display, selected).

---

# RESPONSIVE BEHAVIOR

Desktop

Design first for desktop.

Tablet

Simplify layouts while preserving hierarchy.

Mobile

Prioritize readability and imagery.

Never sacrifice clarity for visual complexity.
